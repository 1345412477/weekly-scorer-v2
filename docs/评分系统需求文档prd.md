# 周报评分系统 v2 — 产品需求文档 (PRD)

## 1. 背景与目标

### 1.1 项目背景
周报评分系统 v2 是一套基于 AI 的周报自动化评分与管理平台。系统当前已完成基础功能建设（上传/评分/排行榜/管理后台），但在用户体验和页面布局方面仍有优化空间。

### 1.2 项目目标
- 简化公共首页，聚焦核心操作（上传 + 排行）
- 重构管理仪表盘，突出重要信息（未提交/低分/进步较大人员）
- 精简管理后台导航，删除冗余页面
- 优化系统设置页布局，提升操作舒适度

---

## 2. 用户角色

| 角色 | 权限 | 主要操作 |
|------|------|---------|
| 匿名用户 | 最小 | 查看首页排行榜、上传周报 |
| 管理员 | 全部 | 仪表盘、周报管理、系统设置、部门人员管理 |

---

## 3. 功能需求

### 3.1 首页轻量化设计（Public Home）

**当前问题**：首页（《Workspace.vue》）双栏加载 WriteReport + Leaderboard，流程引导区占空间大，页面冗长。

**重设计后结构**：

```
┌─────────────────────────────────────────────┐
│  周报评分系统                    [管理员登录] │
├─────────────────────────────────────────────┤
│  ┌───────────────────┐  ┌──────────────────┐│
│  │  提交周报           │  │  排行榜            ││
│  │  (选择提交人)       │  │  排名 │ 姓名│ 部门 ││
│  │  (选择部门 - 自动)   │  │  本周分│ 趋势│ 等级 ││
│  │  (上传文件)          │  │  直出完整排行数据 ││
│  │  ┌──────────────┐   │  │  无手动排序       ││
│  │  │评分结果卡片    │   │  │                   ││
│  │  │提交人: xxx    │   │  └──────────────────┘│
│  │  │部门: xxx      │   │                       │
│  │  │得分: 85       │   │                       │
│  │  │评语: ...      │   │                       │
│  │  │建议: ...      │   │                       │
│  │  └──────────────┘   │                       │
│  └───────────────────┘                         │
└─────────────────────────────────────────────┘
```

#### 3.1.1 页面布局
- 顶部导航：品牌名称（周报评分）+ 管理员登录按钮
- 双栏布局：左侧提交周报，右侧排行榜
- 无流程指引条（删除当前 workflow-strip 区）
- 管理员模式（登录后）不显示此页，直接跳转到仪表盘

#### 3.1.2 排行榜字段调整
| 字段 | 说明 | 数据来源 |
|------|------|---------|
| 排名 | `#1`, `#2`, `#3` ... | 后台排序后返回 |
| 姓名 | 提交人 | `author_name` |
| 部门 | 部门名称 | `department` |
| 本周得分 | 平均分（仅本周数据） | `avg_score` |
| 趋势 | 与上周相比 → 涨/跌/持平 | `trend`（新字段，后端已支持） |
| 等级 | 优/良/一般/差 | `latest_grade` |

- **无手动排序功能**：固定按总分降序排列
- 趋势显示规则：上涨显示绿色 ↑（`> 0`），下跌显示红色 ↓（`< 0`），持平显示灰色 →（`= 0`），无上周数据不显示

#### 3.1.3 提交周报流程优化
- **自动识别提交人并匹配部门**：用户从人员下拉选择后，部门自动填充（当前已实现）
- **评分过程中阻塞**：上传按钮点击后：
  - 按钮显示加载状态，`uploading = true`
  - 页面其他操作不可用（灰色遮罩或禁用交互）
  - 直到评分完成
- **评分结果卡片化**：评分完成后，右侧预览区展示卡片式结果
  - 提交人姓名
  - 部门
  - 综合得分（大号数字）+ 等级标签
  - AI 评语
  - AI 改进建议

#### 3.1.4 后端接口（无需新增）
- `GET /api/v1/leaderboard?period=week&sort_by=total_score` - 排行榜（后端已返回 `trend` 字段）
- `POST /api/v1/reports/upload` - 上传周报
- `GET /api/v1/persons` - 人员列表
- `GET /api/v1/departments` - 部门列表
- `GET /api/v1/reports/{id}` - 获取评分详情

### 3.2 仪表盘重构（Admin Dashboard）

**当前问题**：仪表盘展示统计卡片 + 评分趋势图 + 最近周报，与周报列表页信息重叠，缺少对未提交人员和低分人员的关注。

**重设计后结构**：

```
┌─────────────────────────────────────────────┐
│  仪表盘                                        │
├─────────────────────────────────────────────┤
│  ┌──────┐ ┌──────┐ ┌──────┐ ┌───────────┐  │
│  │总人数 │ │已提交 │ │未提交 │ │提交率     │  │
│  │ 50   │ │ 38   │ │ 12   │ │ 76%      │  │
│  └──────┘ └──────┘ └──────┘ └───────────┘  │
│                                               │
│  ┌──────────────────┐  ┌──────────────────┐  │
│  │ ⚠️ 本周未提交      │  │ 📉 评分较低人员   │  │
│  │ 张三 · 技术部      │  │ 李四 · 62分 · 一般 │  │
│  │ 王五 · 产品部      │  │ 赵六 · 58分 · 一般 │  │
│  │ ...              │  │ ...              │  │
│  └──────────────────┘  └──────────────────┘  │
│                                               │

│  │ 李四 · 上周65→本周78 · 提升+13分          │ │
│  │ ...                                      │ │
│  └──────────────────────────────────────────┘ │
└─────────────────────────────────────────────┘
```

#### 3.2.1 指标卡片（4个）
| 指标 | 来源 |
|------|------|
| 总人数 | Dashboard API → `total_persons` |
| 已提交 | Dashboard API → `submitted_count` |
| 未提交 | Dashboard API → `not_submitted.length` |
| 提交率 | 已提交 / 总人数 × 100 |

#### 3.2.2 本周未提交人员列表
- 显示姓名 + 部门
- 数据来源：`leaderboardAPI.dashboard()` → `not_submitted`
- 为空时显示"本周全部人员已提交"的提示

#### 3.2.3 评分较低人员列表
- 显示本周评分后 30% 的人员
- 显示姓名 + 得分 + 等级
- 数据来源：`leaderboardAPI.dashboard()` → `low_scorers`

#### 3.2.4 进步较大人员 Top5
- 按本周 vs 上周分数差降序排列
- 显示姓名 + 分数变化（上周→本周）+ 提升分值
- 数据来源：`leaderboardAPI.dashboard()` → `top_improvers`
- 为空时显示"暂无进步数据"的提示

#### 3.2.5 后端接口（已有）
- `GET /api/v1/leaderboard/dashboard` - 聚合数据（返回未提交、低分、进步较大人员）
- 无需新增接口

### 3.4 系统设置页 UI 优化

**当前问题**：左侧评分维度 + Prompt 区、右侧阈值 + 测试评分区在宽屏下左右布局，但左右区内部组件高度/宽度不协调，视觉上杂乱；底部人员与部门管理的添加表单与列表布局紧凑。

**优化方案**：

#### 3.4.1 布局重构
```
┌─────────────────────────────────────────────┐
│  [重置默认] [保存配置]                          │
├─────────────────────────────────────────────┤
│  AI 模型状态卡片（不变）                         │
├──────────────────────┬──────────────────────┤
│  评分维度表格          │  等级阈值配置          │
│  （表格宽度100%）      │  （卡片式阈值列表）     │
│                      │                      │
│  AI 评分 Prompt      │  测试评分区域          │
│  （编辑器占满宽度）     │  （文件拖上传 + 结果）  │
├──────────────────────┴──────────────────────┤
│  人员与部门管理                                │
│  ┌──────────────┐  ┌──────────────┐         │
│  │  部门管理      │  │  人员管理     │         │
│  └──────────────┘  └──────────────┘         │
└─────────────────────────────────────────────┘
```

#### 3.4.2 具体优化项
| 区域 | 优化内容 |
|------|---------|
| AI 状态卡片 | 增加 Loading 骨架屏；连接成功/失败状态的视觉反馈增强 |
| 评分维度表格 | 列宽按内容比例分配，操作列固定宽度；表格添加斑马纹；添加/删除按钮调整间距 |
| 等级阈值 | 四个等级卡片等宽排列，输入框统一宽度，百分比显示（如 ≥45分/50分 即 90%）|
| Prompt 编辑器 | 等宽字体，行号标记，与维度区域实现高度同步 |
| 测试评分区 | 结果区域使用卡片分层展示，维度评分条带百分比标签 |
| 部门管理 | 添加表单水平对齐，列表项添加过度动画 |
| 人员管理 | 同上，编辑态保持与列表项一致高度 |

#### 3.4.3 约束
- **不改变任何接口逻辑**，纯 UI 层面优化
- 不修改后端代码
- 不修改 SPA 路由

## 6. 风险与注意事项

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| 排行榜趋势仅支持 week 周期 | month/all 周期 trend 为 null | 前端判断，无趋势时不显示趋势列 |
| Dashboard 数据可能为空 | 新系统第一批周报上传前无数据 | 各列表显示空状态提示 |
| 评分阻塞期间用户误操作 | 导致重复上传或页面跳转 | 使用全局遮罩 + 禁用导航 |
